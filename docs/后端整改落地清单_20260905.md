## 一、本次执行的问题与改动

### 1. RUN-04 后端侧：data-pipeline 的“跳过/失败/成功”机器状态

**问题名（整改清单原文定位）**
> 总控解析真实接口返回 1785836509606；Fiber 解析 1786028387147 —— 缺 review/载荷损坏被当成 0 检查、0 失败。

**仓库侧根因**
- `/agent/data-pipeline` 的 `review` 初始为全 0 计数对象，跳过审查时只加 warnings，最终仍 `success=true`；
- 规则审查异常、GIS/SAFE 模块异常可被吞掉或只追加 errors，DSL 仍可能读到“0 问题”；
- 响应契约没有 `stage_results/review.status` 机器字段，下游只能猜。

**改动内容**
| 文件 | 改动 |
|---|---|
| `schemas.py` | `DataPipelineResponse` 增加可选 `stage_results: Optional[dict]` |
| `api.py` | `review` 增加 `status / executed / reason / error` 字段；新增顶层 `stage_results.parse/review` |
| `api.py` | 审查成功 → `status=executed, executed=true`；跳过 → `status=skipped`（含原因）；异常 → `status=error` |
| `api.py` | GIS/SAFE 模块异常不再 `except: pass`，写入 errors 并把 review 置 error；终态 `status=review_error, success=false` |
| `api.py` | 不可解析/工程加载失败时同步写 `stage_results.parse.status=error` |
| `tests/test_data_pipeline_contract.py` | 契约断言加入 `stage_results` 与 review 状态键；新增 3 个用例（executed / skipped / GIS 异常） |

**验收结果**
- 官方场勘包：`stage_results.review.status=executed`；
- 附件/非可审查文件：`review.status=skipped`，不再伪装“0 风险”；
- GIS 模块抛错：`review.status=error` 且顶层 `success=false`。

### 2. CON-03 / CON-04 后端侧：BOM 行规范字段与对象 ID

**问题名（整改清单原文定位）**
> 施工引擎 pick_materials；主 BOM API 数据结构 —— 后端 BOM 行只有“最终数量”，施工端读“数量/quantity”为空；
> code in related —— C-1/C-10 子串误匹配；完整包所需材料 [:30] 截断。

**仓库侧根因**
- `design_parser/bom_builder.py` 输出只有中文字段，没有 `quantity/unit/source_object_ids` 等规范键；
- 施工端按 `数量/quantity` 读取，导致真实 `/agent/bom` 输出数量为空。

**改动内容**
| 文件 | 改动 |
|---|---|
| `design_parser/bom_builder.py` | BOM 每行同时输出规范键：`rule_code/process/location/material_code/material_name/specification/unit/design_quantity/loss_quantity/reserve_quantity/quantity/design_object/calculation_method/calculation_basis/confidence_status/data_source` |
| `design_parser/bom_builder.py` | 新增 `source_object_ids`：优先真实 `id`，缺失时用 `{kind}:{code}` 稳定回退；全局固定项输出 `[]` |
| `design_parser/bom_builder.py` | 电杆/箱体/光缆/标签/熔接/测试/许可等 add 调用按实际对象分组传入对象 ID |
| `tests/test_bom_builder.py` | 新增规范键与对象 ID 回归测试 |

**兼容性**
- 中文旧字段全部保留（`最终数量/单位/物料编码/对应设计对象` 等不变）；
- `quantity == 最终数量`、`unit == 单位`、`material_code == 物料编码` 由测试锁定；
- 下游施工端仍可读旧键，同时可用新键做精确匹配。

**验收结果**
- 16 口光箱行：`quantity=最终数量`，`source_object_ids=["boite:B1"]`；
- FDT 行：`source_object_ids=["boite:B2"]`；
- 全局项目管理等固定项：`source_object_ids=[]`。
