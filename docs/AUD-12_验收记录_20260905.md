## 三、未解决的原因（三层）

1. **云端未部署**：本仓库已加的 `quantity/unit/material_code/source_object_ids` 只存在于本地代码，`118.31.127.213:8001` 当前返回的仍是旧字段；
2. **BOM 行是聚合行**：`对应设计对象` 为"2条光缆/2个箱体/2根电杆"这类汇总描述，Construction 用对象编码去匹配时全部落空，只能写"详见BOM"兜底；
3. **Construction 引擎未消费 source_object_ids**：即使云端部署新字段，`material_for_codes()` 目前只查 `对应设计对象/design_object/object_code`，不读 `quantity` 的整行匹配条件也不看 `source_object_ids`；即使读到 quantity，聚合行直接分摊到每个对象会产生重复计数，需要确定归属口径。

> 注：Construction 的数量读取本身支持 `数量` 或 `quantity`，单位支持 `单位` 或 `unit`。所以只要 BOM 行带 `quantity/unit` 且能命中对象，数量/单位就能保留；当前缺口主要是"云端未部署 + 行无法命中对象 + 引擎不读 source_object_ids"。

## 四、要真正解决，需要按顺序完成

1. **部署本仓库后端改动**到 `118.31.127.213:8001`（`/agent/bom` 输出 quantity/unit/material_code/source_object_ids）；
2. **修改 Dify 独立施工工具节点**：`material_for_codes()` 支持：
   - 精确匹配 `source_object_ids`（与工程对象 `id` 或 `{kind}:{code}` 对应）；
   - 匹配成功后读取 `quantity/unit`；
   - 聚合行（多对象共享）给出"归属口径"：要么拆成对象级材料行，要么输出"项目汇总材料"并避免按对象重复计数；
3. 重新跑 Dify PROD V1.0 全流程，用本次同样的验收脚本确认 material_rows 全部有 数量+单位+物料编码。
