# 07 业务参数与规则路由说明

> 本地交付文档。业务参数默认值一律为**行业参考默认值，待官方确认**（D01~D07），
> 未定项不在报告中断言为官方口径。更新时间：2026-08-15。

## 1. 业务参数（business_params）

唯一事实源：`design_parser/mappings/business_params.json`；
加载器：`design_parser/business_params.py::load_business_params()`（文件缺失/损坏时回退内置默认值）。

| 参数组 | 键 | 默认值（待官方确认） |
|---|---|---|
| 损耗率 | `loss_rates` | 光缆 500002050=5%、钢绞线 200001033=3%、电杆 poles=0%（备件 2%）、结构件 500002054/500002142=1%、易损件 200000185 等=2~3% |
| 预留长度 | `reserve_lengths` | PCP 盒内余长 1.35m、接头每侧 7.5m、人孔 0.75m、电杆上下杆 7.5m、端点 3.5m |
| 包装取整 | `packaging` | 光缆 2km/盘向上取整；钢绞线 500m/卷；熔接点按实际（exact）；电杆/分路器等按整数向上取整 |
| 利旧 | `reuse` | 标记字段 `reuse`；高可能利旧物料 500002480/500002337/500002159/500004729；钢绞线 200001033 需人工确认；默认 `new_with_notice` |
| 纤芯预留策略 | `fiber_policy` | required_cores 默认 4；每 PCP 熔接 4 芯；贯通熔接 true；停放区端面保护、不计熔接量 |
| 施工指令颗粒度 | `instruction_levels` / `process_cards` | 两级：PCP + 工序（PCP安装/光缆成端与熔接/分光器安装/光路测试） |

- `GET /agent/business-params`：返回上述参数 JSON，供 Dify 工具节点消费。
- BOM 公式（`design_parser/bom_formula.py::compute_bom_quantity`）：
  净量 → 损耗 → 预留（米，KM 单位折千） → 包装取整，输出 `net/loss/reserve/before_pack/final/unit/detail/source`。
- `engineering_data` 对象新增可选 `reuse` 字段（`yes/no`，`_normalize_reuse` 归一化 OUI/YES/1/TRUE/利旧）。

## 2. 规则路由：R005_1 暂不启用（口径待确认）

- **官方规则**：规则库 v2.0 `R-REL-001`（图层表字段说明 校验规则表_行 5.1）——
  提取 SITE(TYPE=PM) 的 CODE 与 ZPM 的 CODE 双向比对，标准值 `SITE.CODE = ZPM.CODE` 一一对应。
- **实现**：`rule_engine.py::check_site_pm_zpm_bidirectional` 与官方文本一致（见 `tests/test_rule_r005_1_official_behavior.py`）。
- **未启用原因**：现有正确案例包（TC-01 2.6 及黎新包 TC-09/TC-10 系列）的编码模型为
  `ZPM.CODE=ZPM-01` + `ZPM.REF_PM=SITE.CODE`，不符合官方 CODE 相等口径；接入路由后每个包固定报 2 条
  R005_1 error，与"正确工程全通过"基线冲突。该口径（是否接受 REF_PM 关联等价）待官方/需求方确认。
- **启用条件**（任一满足后可移除本说明并路由）：
  1. 官方确认接受 `ZPM.REF_PM = SITE.CODE` 关联等价 → 修改规则按 REF_PM 双向校验；
  2. 官方/需求方要求严格执行 CODE 相等 → 保持现实现，同步修正正确案例包 ZPM.CODE 为 SITE.CODE。
- **已路由**：R005_3（CABLE.REF_PM↔SITE.CODE）、R027（PM 在 ZPM 范围内）、R028（PBO 在 ZPM 范围内）、R033（8 个官方图层非空）。
  实测对 TC-01 2.6 / TC-09 / TC-10 均无新增失败。
