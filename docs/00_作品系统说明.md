# 作品系统说明：通信工程智能化全流程交付 Agent

> 系统名称：通信工程智能化全流程交付 Agent（设计解析引擎 V0.3 + Dify 总控工作流）
> 适用对象：通信线路工程（FTTH/FTTx 接入网）设计图、竣工图与工程表格
> 交付形态：后端确定性解析审查引擎（FastAPI）+ 低代码总控编排（Dify 工作流）+ 结构化交付报告

---

## 一、研究背景

通信线路工程（尤其是 FTTH 接入网）在勘察、设计、竣工环节产生大量异构工程数据：QGIS 工程文件（.qgs/.qgz）、Shapefile 空间图层、Excel 物料清单（BOM_LIST）、物料编码库、纤芯拓扑表等。官方审查体系（《图层表字段说明和数据校验规则》）要求对 8 个标准图层、39 条校验规则及 v2.0 扩展规则逐项核查，同时还需输出 BOM 物料清单、纤芯分配方案与施工指令。

当前痛点：

- **人工审查强度大**：单包工程需人工核对图层完整性、字段规范性、容量关系、纤芯占用、BOM 匹配等，人工耗时按实验方案估算约 20~40 分钟/包（待人工侧实测补充），且易漏检；
- **数据规模大**：真实工程 BOM_LIST 达 104 万行、物料编码库 6.5 万余条、纤芯拓扑表 120 个页签，传统读取方式内存与耗时不可控；
- **规则口径复杂**：既有官方同码建模（SITE.CODE=ZPM.CODE），也有外键建模（REF_PM=SITE.CODE）；字段必填/长度/类型需按 v2.0 对齐；
- **交付链路长**：审查 → BOM → 纤芯 → 施工指令需要基于同一工程对象模型贯通，避免各环节数据不一致；
- **可信度要求高**：评审关注“可复现、无幻觉”，AI 报告不得凭空捏造数字。

大赛指标明确提出“BOM/工艺/纤芯自动生成且时间缩短≥50%”，本作品即面向上述背景，构建“确定性规则引擎 + 全流程自动交付”的智能化系统。

## 二、问题分析

| 问题域 | 具体表现 | 影响 |
|---|---|---|
| 数据异构 | 压缩包嵌套（zip/rar/7z）、QGIS 工程、SHP、Excel、PDF 混存 | 单一解析器无法覆盖，需统一解包与识别 |
| 大表读取 | BOM_LIST 104 万行、SRO TOPO 120 页签、物料库 6.5 万+ | 整表加载内存爆炸、响应超时 |
| 规则繁杂 | 39 条官方规则 + v2.0 21 条，含图层/几何/字段/容量/孤立/纤芯/BOM/安全 | 需确定性自动执行并分级阻断 |
| 深埋/非标异常 | 异常编码埋在 5000 行之后；非标箱体类型（如 HUAWEI-UNKNOWN-9999-X）被静默当成标准物料；长度 0.0 不拦截；利旧标记藏在 STATUT=REUSE | 漏检导致错误采购量与错误交付 |
| 口径冲突 | 官方同码模型 vs 工程实际外键模型；字段必填/长度 v2.0 对齐 | 误报或漏报，影响基线稳定 |
| 幻觉风险 | LLM 生成报告可能虚构数据 | 评审不认可、交付不可追溯 |
| 性能瓶颈 | 大包全流程 66.6s+，重复评审重复解析 | 评审/复跑体验差 |

## 三、总体思路

采用“**后端确定性数据源 + 前端低代码编排**”的双层架构：

1. **确定性优先**：所有审查、BOM 计算、纤芯分配均由后端规则引擎/公式模块确定性计算，输出固定结构 JSON；不依赖 LLM 生成任何数字，杜绝幻觉；
2. **单一工程对象模型**：解析层统一输出 `engineering_data`（cable/boite/ptech/site/infrastructure + 对象 ID），审查、BOM、纤芯、施工全部消费同一模型，保证全链路一致；
3. **规则全覆盖可路由**：39 条官方规则 + v2.0 21 条 + 附表规则共 64 条全部自动执行；GIS/安全类规则在具备空间数据时自动并入主流程；
4. **分级门禁与人工兜底**：fatal/error 阻断或进入交付门禁，warning 与不确定项（利旧、非标物料、零值字段）转“待人工确认”，不静默放行；
5. **性能工程**：流式大表扫描、文件级/参数级/流水线级三级缓存、compact 精简响应，支持 104 万行级工程与重复评审秒回；
6. **Dify 总控编排**：后端各接口作为 HTTP 工具被 Dify 工作流消费，输出统一交付报告（工程信息/审查结果/BOM/纤芯/施工/结论）。

## 四、技术路线

| 层级 | 模块 | 职责 |
|---|---|---|
| 解析层 | package / qgs_reader / layer_reader / excel_reader / bom_fiber_reader / pdf_reader | 解压、QGIS 解析、SHP（fiona/pyshp 双后端）、Excel 流式读取、PDF 文本提取 |
| 数据层 | project_data / engineering_data | 字段别名映射、统一对象模型、fiber_tables 注入 |
| 规则层 | rule_engine / gis_rules / safety_rules / case_checks | 64 条规则确定性执行、严重等级、五大问题分类 |
| 计算层 | bom_builder / bom_formula / business_params / construction_kb | BOM 损耗/预留/取整/利旧、纤芯分配、施工指令素材 |
| 接口层 | api.py（FastAPI） | data-pipeline / agent/bom / business-params / gis-check / safety-check / construction-kb 等 |
| 应用层 | Dify 总控工作流 | 全流程编排与交付报告生成 |

数据流：`工程包 → 文件识别分类 → 解包解析 → 工程对象模型 → 规则审查 → BOM/纤芯/施工计算 → 结构化 JSON → Dify 总控 → 交付报告`。

技术选型：Python 3.10~3.14、FastAPI、fiona/pyshp、openpyxl/xlrd 流式读取、paramiko/requests（部署联调）、Dify 工作流（HTTP 工具 + 报告编排）。

## 五、功能设计

1. **工程识别与解析**：自动识别场勘/完整设计/竣工/Excel 工程包，解析 8 个官方图层（IMB/SITE/BOITE/CABLE/PTECH/INFRASTRUCTURE/ZNRO/ZPM），保留空图层与原始字段名；
2. **智能审查（64 条规则）**：
   - 文件/图层完整性（R001~R004、R016、R033）、坐标系（R017）、字段存在与必填（R021、R005）、编码唯一（R007）、字段类型/长度（R018、R032）；
   - 孤立与引用（R005_1~R005_4、R008）、容量（R019/R020/R022）、拓扑（R010/R014/R023）；
   - GIS 空间规则（R-GIS-001~006）、安全距离规则（R-SAFE-001~012）；
   - 纤芯（R-FIBER-001/002）、BOM 匹配（R-BOM-001）；
3. **BOM 权威计算**：官方 29 码 + 4 全局项 → 损耗率 → 预留长度 → 包装取整 → 利旧冲减 → 未收录/非标物料拦截，输出设计/损耗/预留/最终数量与计算依据；
4. **纤芯分配与冲突检测**：已用芯预置占用、新分配跳过已占芯、同路由推断（R-FIBER-002）、容量冲突提示；
5. **施工指令素材**：按 PCP/工序两级输出作业卡（步骤/材料/工艺/测试/安全/验收），规程引用带校验状态；
6. **交付报告**：Dify 总控汇总工程信息、审查统计与问题清单、BOM 表、纤芯接续、施工指令与交付结论（阻断/条件通过/通过）；
7. **工程运维**：2 小时项目 TTL、结果哈希缓存（LRU 32 / TTL 1h / 64MB）、compact 精简、request_id 对账、路径穿越与 SSRF 防护。

## 六、关键技术

1. **流式全量扫表**：BOM_LIST 104 万行以 openpyxl read_only 单遍扫描、按页保留，过滤/翻页内存安全，全表约 6 秒；修复了三处 `limit=5000` 造成的深埋异常码漏检；
2. **确定性规则引擎与门禁**：规则结果统一 severity（fatal/error/warning），`failed_rules` 只计 error/fatal，warning 保留进“待人工确认”，阻断语义可复现；
3. **双向孤立与双口径兼容**：R005_1 支持“同码（SITE.CODE=ZPM.CODE）”或“外键（ZPM.REF_PM=SITE.CODE）”任一满足即通过，避免官方模型与实际建模的误报，同时保留真实孤立检出；
4. **字段口径 v2.0 对齐**：必填字段、长度、类型按官方 v2.0 与 DBF 列宽语义校验（数值列跳过字符串长度比较，修复 float 全精度误报）；
5. **BOM 公式链路**：损耗率附加、预留长度（含弯曲增长千分比）、包装规格向上取整、利旧冲减（reuse 只减新购、不删对象/工序），全链路输出计算依据；
6. **异常拦截增强**：非标箱体类型（官方 l_bpe_type：BPE/BPI/PBO）按 R-BOM-001 error 拦截；零值/负值核心长度字段按 R005 拦截；利旧标记兼容字段值 STATUT=REUSE；
7. **三级缓存**：文件级（文件+参数+修改时间）、表格级、流水线级（SHA256+参数+规则版本）缓存，重复包/复跑秒回；
8. **双矢量后端**：fiona（3.10~3.13）与 pyshp 纯 Python（3.14）自动回退，跨版本部署稳定；
9. **安全加固**：file_url SSRF 防护、路径穿越防护、CORS 白名单、错误响应不泄露 Traceback。

## 七、创新点

1. **规则库全覆盖自动执行**：官方 39 条 + v2.0 21 条 + 附表规则共 64 条全部可自动执行，GIS/安全规则在具备数据时自动并入主流程，单包自动化率 100%；
2. **后端确定性权威数据源，防幻觉**：审查数字、BOM 数量、纤芯分配全部由后端确定性计算，LLM 仅负责报告编排，配合“待人工确认”降级机制，满足“可复现、无幻觉”评审要求；
3. **深埋与隐性异常识别**：突破 5000 行截断实现 104 万行全量扫描；识别非标箱体类型、零值长度、STATUT=REUSE 利旧标记等“藏在字段值里”的异常，避免静默放行与错误采购；
4. **全链路对象模型贯通**：`engineering_data` 对象 ID 贯穿审查问题（object_ref）、BOM 对应对象、纤芯分配、施工对象，对象可追溯率 90%+；
5. **性能数量级优化**：大表流式化 + 三级缓存，本地赛题四 66.6s→36.8s，Dify 全流程 27~39s/包，重复评审秒回；
6. **双口径规则兼容**：同码/外键两种建模并存判定，兼顾官方规范与工程实际，显著降低误报；
7. **低代码可编排**：后端接口与 Dify 工作流松耦合，规则/参数调整无需改动 Dify 应用，便于评审演示与二次开发。

## 八、应用价值

1. **效率提升**：自动全流程实测 27~39 秒/包（首跑），重复评审缓存秒回；时间缩短率按实验方案基准（人工 20~40 分钟/包）估算可支撑“≥50%”指标，正式量化对比数据待人工侧实验采集后补充（模板要求真实原始记录，不以估算值冒充实测）；
2. **质量保障**：21 包标准质检测试集双通道（后端 + Dify）全部 succeeded，赛题一/四基线 287/57/230 精确复现，正确工程 57/57/0 零误报；
3. **规模可扩展**：面向 104 万行 BOM、120 页签纤芯拓扑的真实工程规模设计，可支撑城市级 FTTH 网络的批量质检与交付；
4. **可信交付**：全部结果可复现、可追溯（规则编号/对象 ID/计算依据/条款依据），非标与不确定项显式转人工确认，适合评审、验收与第三方复核；
5. **平台价值**：后端能力以标准 HTTP 接口开放，可被 Dify 等低代码平台、其他 Agent 或内部系统直接集成，具备较强的工程化复用性；
6. **行业适配**：规则库与业务参数（损耗率/预留/取整/利旧/纤芯/施工）全部参数化，可按地区规范或运营商要求配置，无需改码即可适配新口径。
