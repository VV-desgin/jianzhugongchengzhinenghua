### 3.2 纤芯分配工具（FIB-01~05、RAG-01）

文件：`D:\通信建筑工程全流程 Agent 项目\04_Dify工作流\纤芯分配工具（PROD）.yml`
节点：`1785820320131` 纤芯分配引擎（YAML 约 347-394）

本机复核到的关键行为：

1. 已用芯只来自 `engineering_data.fiber_assignments`（由后端 `design_parser/rule_engine.py:3047 build_fiber_assignments` 预置）；引擎**不读取**聚合字段 `nb_fibre_util`，也不校验聚合占用与逐芯表一致性。
   → 若输入没有逐芯表、只带 `nb_fibre_util=24/capacite=24`，`existing=[]`，仍会从 1 号芯开始“分配”4 芯且无冲突（AUD-07 场景）。
2. `get_existing()` 只返回第一条匹配，无“同一光缆重复记录独立检查”；分配循环按 `tube→core` 从最小可用号开始找，占用 2 时会分配 1、3（AUD-09），**不是文档所宣称的连续选芯**。
3. `splice_count = len(splice_table)`，而 `splice_table` 按光缆一行汇总，`splice_count` 实为“光缆汇总行数”，不是接头位置数/逐芯熔接次数。
4. 空 `cables` 列表 → 直接 `status="正常"`、0 分配；非法 `required_cores` 被 `max(1,…)` 强制成 1；`modulo` 不整除容量时无校验。
5. 输入参数 `kb_result` 在纤芯引擎中完全未使用；检索先于计算且无异常降级配置（RAG-01）。
6. 后端仓库没有“纤芯分配接口”，只有预置占用的 `build_fiber_assignments` 和 R-FIBER 规则；因此审查报告所说“已有且已验证的后端 Fiber”在本仓库内**不存在**。

| 编号 | 建议修改 |
|---|---|
| FIB-01 | 优先使用逐芯占用表；同时用聚合 `nb_fibre_util/capacite` 做一致性校验；满占用即阻断；只有聚合数量而无芯号时返回“待确认”，禁止猜空闲 |
| FIB-02 | 输入记录按业务+芯号查重；若声明“连续策略”则实现连续区间搜索（占用 2、需求 2 → 3、4）；否则删除文档中的连续性承诺 |
| FIB-03 | 要么新增后端确定性纤芯分配服务，要么如实限定“PCP 样例逐段候选分配”，把端到端路径/跨段交集/ODF 管理移入规划；固定 required_cores=4 可作为显式项目参数保留 |
| FIB-04 | 输出改名 `cable_allocation_row_count`；真实 `splice_records` 存在时才计算 `splice_location_count`/`splice_core_count`，禁止把光缆行数当熔接工程量 |
| FIB-05 | 区分 `NOT_APPLICABLE`（有效无纤芯需求）与 `FAILED`（缺必要长度/容量/载荷）；需求必须正整数且结构分组明确 |
| RAG-01 | 先确定性计算，知识检索放独立增强分支并配置错误默认值；输出 `retrieval_unavailable`；不要把 LLM 降级等同于整条 RAG 链降级 |

## 五、建议执行顺序
